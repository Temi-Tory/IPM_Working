# Chapter 1 — Introduction

## 1.1 Motivation

Modern infrastructure systems — electricity distribution networks, water and gas distribution systems, transport and logistics networks, drone-based medical delivery corridors — are, almost without exception, analysed as directed networks. An engineer asking "how long will this project take", "how much throughput can this system deliver", or "how likely is this facility to remain reachable if components fail" is, in each case, asking a question about propagation through a directed acyclic dependency structure: task durations propagate along precedence constraints to a completion time; flow propagates along capacitated edges to a delivered throughput; and operational risk propagates along failure-dependent edges to a delivered reliability.

Despite this shared underlying structure, these three questions are, in practice, almost never answered by the same tool, nor from the same model of the network. Scheduling questions are addressed with critical-path-method (CPM) software; throughput questions with dedicated max-flow or discrete-event simulation packages; and reliability questions with reliability block diagrams, fault trees, or Monte Carlo simulation frameworks that model the network from scratch in a bespoke, analysis-specific representation. Each analysis therefore demands its own tool and its own model definition, so that the same physical network ends up represented and maintained multiple times, in parallel, by different (and often incompatible) formalisms. This duplication is not merely an engineering inconvenience. As a system grows — more nodes, more edges, more interacting subsystems — the cost of maintaining several independent representations of the same network grows with it, and the opportunity for the representations to silently diverge grows with it too. More importantly, fragmentation of this kind hides exactly the insight that a network-level analysis is best placed to reveal: a flow bottleneck and a reliability weak point may be the very same edge in the underlying network, yet if throughput and reliability are computed by two unrelated tools operating on two independently constructed models, this coincidence is invisible to the analyst.

This thesis is concerned with the design, theoretical development, and software realisation of a framework that removes this duplication at its source: a single network model, defined once from a directed acyclic graph (DAG) representation of the system under study, that is reused — without modification — as the substrate for multiple, independently exact propagation-based analyses. Each analysis supplies only the parameters specific to its own question (task durations for scheduling, edge capacities for throughput, component reliabilities for reachability); the structural work of parsing, validating, and pre-processing the network into a form amenable to efficient propagation is performed once, and shared.

## 1.2 The Case for Directed Acyclic Graphs

The choice of a directed acyclic graph as the framework's common network representation is not incidental; it is the property that makes exact, single-pass propagation possible at all, and it is examined in detail as a design decision in Chapter 3. Briefly, four properties of DAGs are exploited throughout this thesis:

1. **A DAG admits a topological ordering.** Every node can be assigned a rank such that every edge points from a lower rank to a higher rank. This ordering is not merely convenient — it defines a fixed, dependency-respecting sequence in which every propagation algorithm in this framework processes the network, guaranteeing that a node's value is only computed once all of its dependencies have already been resolved.
2. **Acyclicity guarantees termination.** Because no path can revisit a node, no propagation algorithm defined over a DAG can loop indefinitely; a single forward sweep through the topological order necessarily terminates having visited every node exactly once.
3. **Nodes at the same topological depth are structurally independent of one another**, which exposes an explicit parallelism boundary: nodes within one topological layer may be processed concurrently, since none can depend on another within the same layer.
4. **Propagation is exact and requires no iterative convergence.** Because dependencies never cycle back on themselves, a single forward (and, where required, backward) pass through the topological order is sufficient to compute an exact result — in contrast to networks with feedback, which typically require iterative fixed-point solvers with no closed-form termination guarantee.

These four properties are what allow the framework to promise *exact* answers — not statistically estimated, not iteratively approximated — across all three of its analytical pillars, described next.

## 1.3 The Information Propagation Framework

The system developed in this thesis, referred to throughout as the **Information Propagation Framework (IPF)**, is an integrated Julia-based framework for analysing how failure, time, cost, and capacity propagate through a network modelled as a DAG. Structurally, the framework separates into a shared preprocessing layer and three independent, exact propagation algorithms — described here at a summary level; each is developed in full in its own chapter.

**The shared network model.** Every analysis in the framework consumes the same *unified graph object*: a validated representation of the network's edge list, adjacency indices, source and sink node sets, fork and join node sets, topological iteration sets, and full ancestor/descendant relations for every node — constructed once, from a single parse of the network's structure file, and reused unmodified by every downstream algorithm. This object, its construction, and the rationale for representing it as it is represented, are the subject of Chapter 4 (Network Model) and Chapter 5 (Input Processing Module).

**Diamond decomposition.** A recurring structural pattern in DAGs — a *fork* node whose outgoing paths later reconverge at a *join* node — is, on its own, a purely structural phenomenon: an artefact of how the network branches and reconnects, independent of what is being propagated through it. Left unresolved, this reconvergence is also the single largest obstacle to exact propagation, because paths that share a common ancestor are not statistically or numerically independent of one another, and treating them as if they were leads to systematically incorrect results. The framework identifies every such reconvergent structure — termed a *diamond* — decomposes nested diamonds into a directed acyclic structure of their own, and caches each resolved diamond so that it need not be re-derived when it recurs, or nests, elsewhere in the network. Diamond decomposition is developed as a self-contained structural analysis, independent of any one downstream use, in Chapter 6.

**Three exact propagation algorithms.** Built atop the shared network model — and, in the case of reachability analysis, atop diamond decomposition — the framework provides three independently usable analyses:

- *Critical path analysis* (Chapter 7) generalises the classical forward/backward-pass critical path method into a configurable algebraic recurrence over two user-supplied operators — a *combinator*, governing how multiple incoming paths at a node are reconciled, and a *propagator*, governing how a value compounds along a single edge. Classical time-based CPM is recovered as one particular choice of these operators; cost roll-up, risk propagation, and bottleneck (worst-case) scheduling are recovered as others, all from the same underlying recurrence.
- *Flow capacity analysis* answers how much throughput a capacitated network can actually deliver, via exact maximum-flow computation, together with a suite of derived diagnostics — minimum-cut structure, edge and node sensitivity, structural single points of failure, and exact parametric capacity thresholds. This analysis, and the toolkit built around it, is developed fully in a sibling chapter (Flow Toolkit).
- *Reachability (probability propagation) analysis* computes, for every node in the network, the exact probability that it remains reachable from at least one source given node- and edge-level failure probabilities, resolving the statistical dependence introduced by diamond structures through explicit conditioning. This analysis is developed fully in a sibling chapter (Reachability), building directly on the diamond decomposition of Chapter 6.

**Software realisation.** Beyond its theoretical development, the framework has been implemented as a working software system: a Julia package (`InfoPropFrmwrk`) exposing all three analyses through a single facade module, a REST API server (built on `HTTP.jl`) that exposes each analysis as an independently callable endpoint operating on uploaded network data, and an interactive web application (built with Angular and D3.js) that allows a user to upload a network, inspect its structure and diamond decomposition visually, and run any of the three analyses against it. This end-to-end realisation demonstrates that the theoretical unification argued for in this thesis — one network model, several exact analyses — is not only mathematically coherent but practically deployable.

## 1.4 Research Objectives

The overarching aim of this thesis is to demonstrate that a single, DAG-based network representation, correctly pre-processed once, is sufficient to support multiple independently exact propagation analyses, without any of those analyses re-deriving or re-validating the network's structure for itself. This aim decomposes into the following specific objectives:

1. To establish, formally, why a directed acyclic graph is an appropriate and sufficient representation for propagation-based infrastructure analysis, and to define the structural vocabulary (sources, sinks, fork nodes, join nodes, topological iteration sets, ancestor/descendant relations) used consistently across every analysis in the framework.
2. To design and implement a single, schema-agnostic input-processing pipeline capable of ingesting heterogeneous infrastructure network data and producing one validated, reusable network representation for all downstream analyses.
3. To formalise diamond decomposition as a general structural analysis of reconvergence in DAGs — independent of any single downstream application — including an exact procedure for identifying maximal diamonds, correctly handling diamonds that nest within one another, and caching resolved diamond structures for reuse.
4. To develop an exact algorithm for probabilistic reachability analysis over DAGs that resolves the statistical dependence introduced by diamond reconvergence via explicit conditioning, and to establish its computational tractability is governed by diamond nesting depth rather than raw network size.
5. To generalise the classical critical path method into a configurable algebraic recurrence, capable of representing time-, cost-, and risk-based propagation from a single algorithmic skeleton.
6. To develop an exact maximum-flow-based toolkit for throughput, bottleneck, sensitivity, and structural-reliability analysis of capacitated networks.
7. To realise the resulting framework as deployable software, and to demonstrate, through case studies on real and synthetic infrastructure networks, that the framework produces results consistent with established methods while offering the structural advantages of a unified network model.

## 1.5 Thesis Contributions

The contributions of this thesis are grouped, following convention, into methodological, scientific, and applied contributions.

**Methodological contributions.** A schema-agnostic input-processing methodology capable of ingesting heterogeneous infrastructure data formats into a single validated network representation (Chapter 5); a general-purpose, exact diamond-decomposition procedure for identifying and resolving nested reconvergent structures in DAGs, independent of any specific downstream propagation algorithm (Chapter 6); a generalisation of the critical path method to an arbitrary algebraic combinator/propagator pair, unifying time-, cost-, and risk-propagation under one algorithmic skeleton (Chapter 7).

**Scientific contributions.** An exact algorithm for network reachability analysis (the Information Propagation Algorithm) that resolves diamond-induced statistical dependence through progressive conditioning and supernode caching, together with a formal characterisation of its computational complexity in terms of diamond nesting depth and conditioning-set size, rather than network size alone (developed in the Reachability chapter); a demonstrated correctness and performance comparison against an established message-passing reachability method (developed in the Reachability chapter).

**Applied/software contributions.** A complete, open Julia implementation of the framework (`InfoPropFrmwrk`), type-parametric over exact (`Float64`), interval, and probability-box uncertainty representations, sharing one propagation engine across all three; a REST API and interactive web application exposing the framework's analyses to non-programmatic users; and evaluation of the framework across real and synthetic infrastructure case studies, including a bnlearn benchmark network, a metropolitan transit network, and a family of Pareto-optimal drone medical-logistics network designs.

## 1.6 Structure of the Thesis

The remainder of this thesis is organised as follows. **Chapter 2** situates the framework's approach relative to existing methods for scheduling, throughput, and reliability analysis of networks. **Chapter 3** (Network Model) establishes the DAG-based network representation used throughout the thesis: what is meant by a network in this context, how source, sink, fork, and join nodes are defined, and why a directed acyclic representation is both necessary and sufficient for exact single-pass propagation; it precedes and motivates **Chapter 4** (Input Processing Module), which develops the concrete pipeline that parses heterogeneous infrastructure data into the validated network representation defined in Chapter 3. **Chapter 5** (Diamond Decomposition) develops, as a self-contained structural analysis, the identification, nesting resolution, and caching of reconvergent diamond structures within a DAG. **Chapter 6** (Reachability) builds on Chapter 5 to develop the framework's exact probabilistic reachability algorithm. **Chapter 7** (Critical Path) develops the generalised critical-path recurrence and its time/cost/risk specialisations. **Chapter 8** (Flow Capacity) develops the exact maximum-flow toolkit and its derived sensitivity, structural, and parametric-threshold diagnostics. **Chapter 9** describes the framework's software realisation — the API server and interactive web application — and its use in exposing the preceding chapters' algorithms to practical case studies. **Chapter 10** concludes, summarising the thesis's contributions, discussing their limitations, and identifying directions for future work.
