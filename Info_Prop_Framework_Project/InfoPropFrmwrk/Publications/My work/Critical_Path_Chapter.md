# Chapter 7 — Critical Path Analysis

## 7.1 Introduction

The critical path method (CPM) is, in its classical form, a scheduling technique: given a set of tasks, their durations, and the precedence constraints between them, CPM computes the shortest possible completion time for the overall project and identifies the sequence of tasks — the critical path — whose delay would delay the project itself. Read structurally, however, CPM is doing something more general than scheduling. It is computing, for every node of a directed acyclic graph, the *longest* accumulated value reachable from any source, where a task duration is a node value, a precedence constraint is a directed edge, and "accumulated" means "summed along a path, with concurrent paths reconciled by taking whichever is largest." Nothing in this restatement is specific to time. If task durations are replaced with monetary costs, the same recurrence computes the largest possible cost accumulated along any single path — a cost roll-up. If reconciliation of concurrent paths is changed from "take the largest" to "take the smallest," the same recurrence computes an optimistic (best-case) schedule instead of a worst-case one. If the manner in which a value compounds along an edge is changed from addition to multiplication, the same recurrence computes multiplicative risk accumulation rather than additive delay.

This chapter develops that generalisation directly: a single algebraic recurrence, parameterised by two operators supplied by the analyst, of which classical time-based CPM is recovered as one specific instantiation among several. The recurrence is defined over the same network model and topological iteration-set decomposition established in Chapter 3, and — as discussed explicitly in Section 7.9 — makes no use of the diamond decomposition developed in Chapter 5, for reasons that are themselves instructive about what diamond decomposition is, and is not, needed for.

**Structure of the chapter.** Section 7.2 recalls the classical, time-based critical path method, to fix vocabulary and to serve as the reference case against which the generalisation is checked. Section 7.3 develops the generalised algebraic recurrence and its two configurable operators. Section 7.4 describes the node and edge value types used by the framework's implementation, including an explicit non-negative time type whose purpose is to enforce a domain invariant at the type level rather than by scattered runtime checks. Section 7.5 develops the forward pass that computes the recurrence itself. Section 7.6 develops the backward pass used to recover slack. Section 7.7 addresses path reconstruction, and the requirement — not shared by the forward pass — that the node-combination operator be invertible. Section 7.8 presents the time-, cost-, and risk-based specialisations of the generic machinery. Section 7.9 explains why this chapter's analysis, unlike Chapter 6's, requires no diamond decomposition. Section 7.10 closes the chapter.

## 7.2 The Classical Critical Path Method

Classical CPM operates over a project network — a DAG in the sense of Chapter 3 — in which each node $v$ carries a non-negative duration $d(v)$, and each edge $(u,v)$ may carry an additional non-negative dependency delay $\delta(u,v)$ (frequently zero, representing simple precedence with no extra lag). The method proceeds in two passes.

The **forward pass** computes, for every node $v$, its *early start* $\text{ES}(v)$ and *early finish* $\text{EF}(v) = \text{ES}(v) + d(v)$, by a single sweep over the network's topological order (Definition 3.8): a source node's early start is the project start time; every other node's early start is the maximum, over its parents $u \in \text{pa}(v)$, of $\text{EF}(u) + \delta(u,v)$. The project's overall completion time is $\max_{v \in V} \text{EF}(v)$.

The **backward pass** computes, for every node $v$, its *late finish* $\text{LF}(v)$ and *late start* $\text{LS}(v) = \text{LF}(v) - d(v)$, by a symmetric sweep in reverse topological order: a sink node's late finish is fixed at the project's overall completion time; every other node's late finish is the minimum, over its children $w \in \text{ch}(v)$, of $\text{LS}(w) - \delta(v,w)$.

The **total slack** of a node, $\text{LS}(v) - \text{ES}(v)$, measures how much the node's start may be delayed without delaying the project overall. The **critical path** is the set of nodes with zero slack — equivalently, the (generally non-unique) path or paths through the network whose early and late schedules coincide throughout.

This is the reference case the remainder of the chapter generalises: the forward pass is a max-combination, additive-propagation recurrence over node durations; the backward pass is its structural mirror; slack is the difference between the two passes' results at each node.

## 7.3 A Generalised Algebraic Recurrence

**Definition 7.1 (Combinator and propagator).** A *combinator* $\oplus$ is a binary operator, applied over the values a node's parents contribute to it, that reconciles multiple incoming contributions into one. A *propagator* $\otimes$ is a binary operator, applied to a parent's own value and the value carried by the edge connecting it to a node, that determines how much of the parent's value is actually transmitted along that edge.

**Definition 7.2 (Generalised critical-path parameters).** A generalised critical-path problem over $G=(V,E)$ is specified by a tuple $(\nu, \epsilon, \iota, \oplus, \otimes, f)$, where $\nu: V \to T$ assigns each node a value in some value domain $T$, $\epsilon: E \to T$ assigns each edge a value, $\iota \in T$ is the initial value assigned to source nodes, $\oplus$ and $\otimes$ are as in Definition 7.1, and $f: T \times T \to T$ is a *node function* combining a node's own value $\nu(v)$ with the reconciled contribution of its parents.

**The forward recurrence.** For a source node $v \in S$, the propagated value is $\iota$. For any other node $v$, with parents $\text{pa}(v) = \{p_1,\dots,p_m\}$:
$$
\text{value}(v) = f\Big(\nu(v),\ \bigoplus_{i=1}^{m} \big(\text{value}(p_i) \otimes \epsilon(p_i,v)\big)\Big)
$$
Classical CPM (Section 7.2) is recovered by setting $\oplus = \max$, $\otimes(a,b) = a+b$ (so that $\text{value}(p_i)\otimes\epsilon(p_i,v)$ is $\text{EF}(p_i)+\delta(p_i,v)$), and $f(a,b) = a+b$ with $\nu(v)=d(v)$, so that $\text{value}(v)=\text{EF}(v)$ directly. The generality of Definition 7.2 is realised by varying $\oplus$, $\otimes$, and $f$ independently of one another; Table 7.1 lists the pairings the framework provides as built-in choices, together with the analysis each recovers.

**Table 7.1 — Combinator/propagator pairings and the analyses they recover.**

| Combinator $\oplus$ | Propagator $\otimes$ | Analysis recovered |
|---|---|---|
| $\max$ | additive ($a+b$) | Classical CPM — worst-case (longest-path) time scheduling |
| $\min$ | additive | Optimistic scheduling / shortest-path routing |
| $\text{sum}$ | additive | Cost roll-up — total cost accumulated across all incoming contributions, rather than the largest single one |
| $\max$ | multiplicative ($a \times b$) | Risk propagation — the largest compounded risk carried along any single path |

A further class of combinators, exemplified by a *weighted combination* (a weighted sum of parent contributions rather than a strict $\max$/$\min$/$\text{sum}$), is supported for cases in which no single reconciliation rule dominates and a graded blend of the incoming contributions is required instead.

The correctness of the forward recurrence for any choice of $(\oplus,\otimes,f)$ follows directly from Chapter 3's justification of the DAG representation: because a topological order exists (Definition 3.8), every node's parents are guaranteed to have already been assigned a value by the time the node itself is processed, so the recurrence above is well-defined and requires no iteration to converge — it is evaluated exactly once, per node, in a single forward sweep, regardless of which operators are chosen. This is the direct analogue, for critical-path analysis, of the exactness argument given in Chapter 3 (Section 3.5, Consequence 4) for the framework's other propagation algorithms.

## 7.4 Node and Edge Value Types

For the classical time-based case, the value domain $T$ of Definition 7.2 is instantiated as an explicit *non-negative time* type, rather than a bare floating-point number. This is a deliberate design choice, not merely a units convenience: a time-based critical-path computation in which an intermediate value were permitted to go negative — through, for instance, an incorrectly signed dependency delay, or a slack computation gone wrong — would silently produce a nonsensical schedule rather than failing visibly at the point the error was introduced. Representing time as a distinct type whose arithmetic operators (addition, subtraction, multiplication, division, minimum, maximum) each re-validate non-negativity on every application — and raise an error immediately if an operation would produce a negative result — moves this invariant out of scattered runtime assertions in the algorithm code and into the type itself, so that *any* code path manipulating a time value, including future extensions, inherits the guarantee automatically. A companion parameter structure allows task durations and dependency delays to be supplied in mixed units (hours, days, weeks, minutes, seconds and finer), converted to a common internal unit at construction time.

For cost- and risk-based specialisations (Section 7.8), the value domain $T$ is not constrained to this non-negative-time type; the generalised recurrence of Section 7.3 is defined over an arbitrary value domain, and the framework's cost and severity specialisations supply their own node/edge value types appropriate to those domains.

## 7.5 The Forward Pass

The forward pass realising Definition 7.2's recurrence is implemented as a single sweep over the network's iteration-set decomposition (Definition 3.9), processing nodes layer by layer exactly as every other propagation algorithm in this framework does: for each node in the current layer, the values already computed for its parents (necessarily in strictly earlier layers, by Definition 3.9) are propagated across their respective edges via $\otimes$, reconciled via $\oplus$, and combined with the node's own value via $f$, exactly as in the recurrence above. The pass additionally records, for the network as a whole, the maximum value attained at any node (the *critical value*) and the set of all nodes attaining it (the *critical nodes*) — the direct generalisation of the classical critical path's overall completion time and the set of nodes lying on some critical path.

## 7.6 The Backward Pass and Slack

The backward pass mirrors Section 7.2's classical construction: sink nodes are seeded with the overall critical value found by the forward pass, and a reverse sweep over the iteration-set decomposition computes each node's late-finish value as the minimum, over its children, of the child's late-start value less the connecting edge's value — the structural mirror of the forward pass's maximum-of-parents recurrence. Early start, late start, and total slack are then derived directly from the forward and backward passes' results, exactly as in Section 7.2.

Unlike the forward pass, the backward pass as implemented is specific to the additive case ($\otimes(a,b) = a+b$, $f(a,b)=a+b$): recovering a late-start value from a late-finish value requires *subtracting* a node's own duration, which presupposes that the node/edge combination is invertible by subtraction. This is not a limitation of Definition 7.2 in general — a fully generic backward pass could, in principle, be defined for any invertible $f$ and $\otimes$ — but the framework's present implementation provides the backward pass, and the slack it yields, only for the additive case that classical CPM itself requires. Non-additive specialisations (Section 7.8) accordingly make use of the forward pass and the critical-value/critical-node results it produces, but not of slack.

## 7.7 Path Reconstruction

Reporting *that* a project's completion time is some value $V^*$ is frequently less useful to an analyst than being able to report *which* sequence of nodes attains it. Path reconstruction works backward from a critical node, at each step asking which parent's propagated contribution is the one that was actually selected by the combinator $\oplus$ at the current node, and recursing into that parent. For the additive case, this reduces to inverting $f$ and $\otimes$ directly — subtracting the node's own duration, then subtracting the edge's delay, to recover the exact value expected of the selected parent. For the general case, the framework requires the analyst to supply an explicit *inverse node function*, since not every $f$ admits a closed-form inverse.

A specific and instructive failure mode arises when $\oplus = \max$ (or $\min$) and two or more parents' propagated contributions are exactly tied: the combinator itself provides no way to distinguish which parent was "the" one selected, because none was — the reconciliation is genuinely indeterminate between them. The framework's implementation of the max-case inverse detects this condition explicitly and raises an error rather than silently reporting an arbitrary one of the tied parents as though it were uniquely determined; a caller wanting a specific tie-breaking rule (earliest parent index, lexicographically smallest, or similar) must supply one explicitly, rather than have one imposed implicitly by iteration order. This is a direct, if minor, illustration of a theme that recurs throughout this thesis: correctness is preferred over silent convenience wherever the two are in tension.

## 7.8 Specialisations

The generic machinery of Sections 7.3–7.7 is not, in the framework's implementation, exposed only as an abstract recurrence that an analyst must instantiate from first principles for every use; three concrete specialisations are provided directly, each simply a particular choice of $(\nu,\epsilon,\iota,\oplus,\otimes,f)$ within Definition 7.2.

- **Time-based critical path** instantiates the recurrence with the non-negative time type of Section 7.4, $\oplus=\max$, additive $\otimes$ and $f$ — recovering classical CPM exactly, together with its backward pass and slack.
- **Cost-based critical path** instantiates the recurrence over a monetary cost domain, again with $\oplus=\max$ and additive propagation, answering "what is the largest cost that could accumulate along any single dependency path", as distinct from a simple total-cost sum across the whole project.
- **Severity analysis** instantiates the recurrence with a custom combinator that takes the maximum severity across contributing parents, illustrating the framework's support for combinators outside the max/min/sum family described in Table 7.1, wherever an analysis calls for one.

Each specialisation is a thin parameterisation of the same forward-pass sweep (Section 7.5); no specialisation-specific propagation code is required, which is precisely the payoff the generalisation of Section 7.3 is intended to deliver — one algorithm, several analyses.

As an illustration of the time-based specialisation applied to a real system, the framework has been evaluated against a 32-node, 66-edge wastewater treatment network (constructed from a dataset originally due to Jensen et al., 1989), comparing a longest-path (classical worst-case CPM) scenario against a highest-accumulated-load scenario obtained from the same network and the same recurrence under a different combinator/propagator pairing — a direct demonstration that Table 7.1's pairings are not merely a theoretical taxonomy but produce materially different, individually meaningful, results on the same underlying network.

## 7.9 Why This Chapter Does Not Require Diamond Decomposition

Chapter 5 developed diamond decomposition to resolve a specific correctness hazard: when two or more paths into a join node share a common ancestor, and the quantity being propagated is a *probability*, treating those paths as independent double-counts the shared ancestor's contribution — a genuine, otherwise silent, error. It is worth being explicit about why the critical-path recurrence developed in this chapter does not share this hazard, since the framework's own implementation imports the diamond-decomposition module into its critical-path code without ever actually calling into it, a detail that is itself instructive rather than a stray dependency.

The forward recurrence of Definition 7.2 reconciles multiple incoming contributions at a join node via the combinator $\oplus$ — typically $\max$, $\min$, or $\text{sum}$ — applied directly to deterministic values, not to probabilities of an event. There is no notion, in this recurrence, of two paths' contributions needing to be treated as "independent" or "dependent" of one another in the probabilistic sense Chapter 6 is concerned with: $\max$ (or $\min$, or $\text{sum}$) of two numbers is simply $\max$ (or $\min$, or $\text{sum}$) of two numbers, regardless of whether the two paths that produced them shared upstream ancestry. A join node fed by two paths that reconverge from a common ancestor is, from the point of view of Section 7.3's recurrence, no different from a join node fed by two entirely unrelated paths: both are combined by the same $\oplus$, correctly, without any need to identify or condition on shared ancestry.

This is the clearest illustration in the thesis of the boundary Chapter 5 drew deliberately around diamond decomposition: reconvergence is a structural fact about a DAG, present or absent regardless of what is propagated through it, but *whether that reconvergence needs special handling* depends entirely on the algebraic nature of what is being propagated. Deterministic max/min/sum accumulation, as used throughout this chapter, does not need it; the conditional-probability computation of Chapter 6 does. Diamond decomposition, developed once in Chapter 5 as a general structural analysis, is available to be used by exactly the analyses that need it, and is correctly bypassed by the one — this chapter's — that does not.

## 7.10 Summary

This chapter has generalised the classical critical path method into an algebraic recurrence parameterised by a combinator and a propagator (Section 7.3), recovering classical time-based CPM, cost roll-up, risk propagation, and optimistic scheduling as specific instantiations of one shared skeleton (Table 7.1); developed the forward pass realising this recurrence (Section 7.5) and the additive-specific backward pass and slack computation that accompanies the classical case (Section 7.6); addressed the additional requirement of operator invertibility, and its explicit failure mode under tied maxima, needed for path reconstruction (Section 7.7); presented the framework's time, cost, and severity specialisations (Section 7.8); and argued explicitly why this chapter's deterministic accumulation, unlike Chapter 6's probabilistic propagation, requires no diamond decomposition (Section 7.9). Together with Chapter 6 (Reachability) and the companion Flow Toolkit chapter, this chapter completes the thesis's account of the three exact propagation analyses built atop the shared network model of Chapters 3–4.
